tab-jev

A jev-like model + a tabular foundation model =
an in-context learner for your text & tabular data

upstream: github.com/edamame-labs/tab-jev · Apache-2.0 · pre-release v0.1.0.dev0

The problem it solves

  • Classification on data that mixes text (reviews, tickets, pitches) and table (numbers, categories)
  • Only a few labeled rows — dozens to a few thousand
  • You act on the probability: approve · escalate · block
  • Typical: churn, fraud & claims screening, lead scoring, ticket escalation

An LLM reads the text on day one — but can't see your table columns.
A tabular model fuses columns — but needs labels and can't read prose.

tab-jev: let each plane do what it's good at, then combine.

Two pluggable planes

Jev plane — reads text

  • Typed judgments: chosen option + probabilities
  • Jev request/response shape (TypeSafe API), or any LLM via logprobs/sampling
  • JevHTTP, OpenAICompatibleJev adapters included

Tab plane — learns from labeled rows

  • Tabular foundation models (TabPFN, TabICL) predict by in-context learning — no training loop
  • Any scikit-learn-style classifier works

Flow: jev reads text → probabilities become new numeric columns → tab ICL-learns on table + jev columns.

tab-jev hosts no models — both planes are Protocols. Bring your own backends.

Why not just one model?

  • Jev alone — day-one answers, but blind to your table columns
  • Tabular alone — fuses all columns, but needs labels, can't read prose
  • 10k+ labels — a supervised model (TF-IDF, embeddings, fine-tuning) wins

tab-jev's regime: text and table EACH carry part of the signal, labels are scarce.

The contract: Question / Answer

  • Question(type, instructions, criteria) — Jev's /v1/systemone shape
  • noul yes/no → single probability   choice options → distribution   score 2–10 levels → distribution
  • Answer(type, noul, choice, probabilities, confidence, legend)
  • Backends declare probability_source: native / logprobs / sampling
  • Rubrics: extra questions about text columns → each option's probability becomes a new numeric column for tab

Pipeline machinery

  • jev_then_tab — jev features + jev answer; tab predicts from everything
  • tab_then_jev — tab first; jev makes the final call with tab's OOF probabilities + labeled examples in state
  • parallel_blend — both predict independently; cross-validated weighted average
  • Out-of-fold by construction — no row's own label leaks into its features
  • Graceful degradation — no labels → tab skips, jev answers; TabLimits violations fail loud before the backend is called
  • Few-shot — shots=N puts class-balanced labeled examples into jev's state

Exploratory findings (offline notebook)

  • Toy rule: buy = good review AND price < 70 — each plane carries half the signal
  • Fake keyword-jev + LogisticRegression: tab receives [price, features:review.sentiment=±, jev:yes/no]
  • Zero labels → pipeline skips tab, jev answers alone (skipped = {'tab'})
  • Memorizing-tab fake proves the OOF machinery — no self-label leakage
  • TabLimits(max_rows=10) on 400 rows → rejected loudly before the backend is called
  • All three compositions beat jev-only on the toy rule (AUC 0.90–1.00 in-sample)
  • 23/23 repo tests pass on Python 3.12

Intuition cheat-sheet

  • jev = a colleague reading the text, returning calibrated-ish bets — great priors, blind to structured facts
  • tab = a colleague staring at the spreadsheet — great at numeric patterns, can't read prose
  • rubrics = the questions you'd brief the reader with — fixed a priori, they become the bridge columns
  • labels = the truth that lets tab learn how much to trust jev — with zero labels you get jev's raw prior; with hundreds, tab corrects it
  • OOF machinery = honesty — few-label setups are where leakage hides; the pipeline refuses it structurally

Status & fit

  • Pre-release v0.1.0.dev0 — API will change; core is small (pipeline.py ~100 lines)
  • Use when: few labels, mixed text+table, probability-driven decisions
  • Don't use when: no labels at all (jev alone) or 10k+ labels (supervised wins)
